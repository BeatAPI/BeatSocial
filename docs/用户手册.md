# BeatSocial 用户手册

写给运营负责人：你不需要懂代码。网页只用来看，所有决定都在和 Claude Code 或 Codex 的对话里说。两者可以通过 MCP 使用同一份运营数据。

## 一句话

AI 写稿，你在对话里说哪条行、哪条改，bot 按时发布并回收数据，系统每周把数据变成下周的写法和配额。

## 打开看板

双击 `beat-social/打开审核台.command`，浏览器打开 http://127.0.0.1:9361 。看板是只读的，上面没有按钮，不会误改任何东西。

| 页面 | 看什么 |
|---|---|
| 今天 | 待审多少、过档没发多少、各渠道的稿还能撑几天、待你确认的配额 |
| 市场 | 6 个市场（英文、日文、韩文、繁中、俄语、中文大陆）：各自主推什么、用哪些渠道、各渠道待审几条 |
| 帖子 | 左边选市场和渠道，右边按日期看帖子：正文、图和视频、AI 审稿意见、红黄提醒 |
| 数据 | 按渠道、市场、平台、内容类型看表现 |
| 渠道账号 | 所有渠道账号，按市场分组 |
| 竞对 | 对标样本库 |
| 规则 | AI 提出的写法规则，哪些已生效 |

卡片上的红色条是阻断项（批不了），黄色条是要核价，灰色条只是提醒。

## 在 Claude Code 里这样说

| 你说 | 会发生什么 |
|---|---|
| 「看一下今天要处理什么」 | Claude 按市场列出待审、过档、库存和待确认的事 |
| 「把日文市场待审的过一遍」 | 一条条给你看正文、图和提醒，你逐条说意见 |
| 「英文 X 明天 21:30 那条开头太弱」 | Claude 改稿，生成新版本给你看 |
| 「这三条可以发」 | Claude 带着你这句原话批准，记进操作记录；含价格的会先问你核过价没有 |
| 「这条不行，重写」 | 打回，原因留给写稿 AI |
| 「复盘上周」 | 生成复盘，讲结论，给配额建议和规则提案 |
| 「R3 采纳」「下周配额确认」 | 规则生效、配额生效 |
| 「日文市场主推改成视频模型教程」 | 更新市场主推方向，之后的写稿都按它来 |
| 「下周的稿写一下」 | 生成帖子位 → 按市场批量写 → 独立 AI 审稿 → 给你汇报 |

改完刷新看板就能看到。

## 一周节奏

- **周一**：Grok 生成复盘。你说「复盘上周」看结论，再确认配额和规则。
- **周二**：你说「下周的稿写一下」，Claude 批量写，并交给独立 AI 审稿。
- **每晚**：你说「把明后天待审的过一遍」，逐条说行或改。
- **其余时间**：bot 到点领取已批准的稿，发布、回传链接，24 小时和 7 天后采数据。

## 常见问题

- **为什么某条批不了？** 有红色阻断项。让 Claude 按提示改。
- **改了一个字为什么又要重新批？** 批准绑定那一版内容，bot 只会发你批过的版本。
- **数据为什么显示「—」？** 拿不到的数据记为未知，不当成 0。
- **Mac 关机了怎么办？** 初版里 Mac 关机就不发，开机后接着发；过档 6 小时以上的要你决定改时间还是取消。
- **素材怎么放？** 图片或视频放进 `beat-social-data/media/`，跟 Claude 说「这条配图用 media/xxx.png」。

## MCP 对话入口

接入方法见 [MCP 接入与对话流程](MCP接入与对话流程.md)。网页和原有命令用法保持不变。你仍然用上面的自然话表达要求；AI 优先用 MCP 查找和修改。换会话后可从当前帖子版本继续。

AI 会把当前帖子、首评、素材和审稿意见展示给你，再执行你明确说出的批准。帖子变过时会重新展示；bot 已领取时会先核对发布进度。批准完成只表示进入待发布流程，实际发布以回执为准。
