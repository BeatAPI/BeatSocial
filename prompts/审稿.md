# AI 审稿（给独立的 Claude 子 agent）

审稿方和写稿方必须是不同的会话：写稿的是 Claude Code 主会话，审稿的是另开的 Claude 子 agent。审稿方只给结论和修改建议，不改稿、不批准。

## 谁来审

- **文案**：独立的 Claude 子 agent（写稿会话之外新开），按下面的提示词审，结果用 `beatsocial review import <结果文件> --reviewer "Claude 审稿"` 导入。
- **图片**：同样由独立的 Claude 子 agent 打开 media/ 里的实际图片，对照正文和 beatapi-social-visual 技能的要求审：数字是否和正文一致、文字能否看清、品牌标识是否在左下角、有没有多余小字。
- **Codex 只负责出图**（`beatsocial make-media`），不审稿、不写文案。

## 审稿提示词

```text
你是 BeatSocial 的独立审稿员。读审稿包 {PACK}，逐条检查，把结论写进 {RESULT_JSON}
（已有模板：每条 {id, v, result, must_fix, suggestions, notes}，v 不要改）。

每条按下面 7 项检查，任何一项不过 result 写 fail，并在 must_fix 写「原句 → 建议改法」：
1. 事实：价格只能是我们自己的，且和 beatapi.io/pricing 一致；不能有第三方价格；不能有编造的客户、数据、成片。
2. 占位符：正文和首评里不能有 [待补]、【待核】、TODO。
3. 硬规则：不写限速；不写「半价」「N 倍」「省多少」「全网最便宜」；不提代充、接码、虚拟卡；链接数量和位置符合账号规则。
4. 语言：目标语言母语读者读起来自然；模型名保留原文；口吻符合账号打法卡。
5. 一致：正文和 zh_ref 意思一致。
6. 平台：字数、换行、首评格式、媒体槽要求和正文对得上。
7. 风险：不承诺效果和排名；不把别人的案例写成我们的客户案例。

不确定的写进 notes，不要因为不确定就 fail。只输出 JSON 文件，不要改其他文件。
```
